# How the Claude Code MCP Assignment Flow Works

> Audience: recruiters and candidates using the take-home Assignment feature, plus whoever's
> supporting them. Covers the shipped feature (MCP companion on top of the existing take-home
> Assignment/`AssignmentSubmission` flow) — not the future "AI Fluency for Teams" product
> (see `docs/PRD_ai_fluency_teams.md` for that).

## The idea in one paragraph

A recruiter attaches a take-home project ("Assignment") to a job and invites a shortlisted
candidate. The candidate builds it using **Claude Code**, and instead of just clicking a web
link, can connect their own Claude Code to Nideknil's backend over MCP to fetch the brief and
check submission instructions conversationally. When they submit their session transcript, the
backend scores *how they collaborated with AI* (not just the final code) against an 8-dimension
rubric. Separately, the recruiter can connect their **own** Claude Code to a different MCP
server to ask natural-language questions about a candidate's report right before an interview.

Two independent MCP servers, two different credentials, two different trust models:

| | Candidate server | Recruiter server |
|---|---|---|
| URL | `https://api.nideknil.in/mcp/` | `https://api.nideknil.in/mcp-recruiter/` |
| Auth | the `access_token` from their invite | a `RecruiterMcpApiKey` they generate themselves |
| Scope | their own assignment only | any job/submission **they own** |
| Tools | `get_assignment_brief`, `get_submission_instructions` | `list_submissions`, `get_candidate_report`, `ask_about_candidate`, `generate_interview_questions` |

**Note the trailing slash on both URLs above — it's required.** A bare `/mcp` or `/mcp-recruiter`
(no trailing `/`) 307-redirects, and that redirect currently resolves to an `http://` URL behind
this app's reverse proxy, which breaks real MCP clients. Always use the URL with the trailing
slash. (Every command generated by the backend — invite emails, the recruiter key response —
already includes it; this only matters if you're typing a connect command by hand.)

## What the Recruiter does

### 1. Create the assignment
On the job's page → **Assignments** tab → **New assignment**. Fill in:
- **Title** and **brief** (be specific — features, constraints, what "done" means)
- **Evaluation focus** (optional) — e.g. "backend-heavy, I care about API design reasoning"
- **Deadline** (optional)

### 2. Invite candidates
From the same page, **Invite** → pick candidates from the job's applicant pool, or type emails
directly. Each invited candidate gets an `AssignmentSubmission` row with a unique `access_token`
and an invite email containing:
- A link to the web portal (`https://www.nideknil.in/assignment/<token>`)
- A ready-to-run `claude mcp add` command using that same token

### 3. (Optional) Connect your own Claude Code for interview prep
Generate a key from **Recruiter → Claude Code (MCP settings)** → **Generate new key**. Copy the
`connect_command` shown (shown once — copy it now) and run it:
```bash
claude mcp add --transport http nideknil-recruiter https://api.nideknil.in/mcp-recruiter/ \
  --header "Authorization: Bearer <your key>"
```
Verify: `claude mcp get nideknil-recruiter` should show `✓ Connected`.

### 4. Track submissions
The Assignments page shows each candidate's status (`invited → submitted → processing →
analyzed`/`failed`) and, once analyzed, their score. A green "connected via Claude Code" tag
appears once a candidate has actually connected their MCP server.

### 5. Use the interview copilot right before talking to a candidate
In a Claude Code session on your `nideknil-recruiter` connection, ask things like:
- *"list my submissions for job 12"*
- *"get the report for submission 7"* — pulls the real score, dimension breakdown, and summary
- *"what should I ask them in the interview"* — drafts questions grounded in their actual report
- *"how did they use AI to debug"* (free-form) — `ask_about_candidate`

You will only ever see submissions on jobs **you** own — this is enforced server-side, not just
hidden in the UI.

## What the Candidate does

### 1. Get invited
You'll receive an email once a recruiter shortlists and invites you. It has two ways in — a web
link, and a `claude mcp add` command. You don't have to use MCP at all; the web portal alone is
a complete path.

### 2. (Optional) Connect Claude Code
Run the command from the email (or copy it from the portal page):
```bash
claude mcp add --transport http nideknil-assignment https://api.nideknil.in/mcp/ \
  --header "Authorization: Bearer <your access_token>"
```
Verify: `claude mcp get nideknil-assignment` should show `✓ Connected`.

### 3. Ask for the brief instead of tab-switching
In a Claude Code session on that connection:
- *"what's the brief for this assignment"* → returns title, brief, deadline, company, job title
- *"how do I submit"* → returns the exact submit command

### 4. Build the assignment
Just work normally in Claude Code. Nothing about how you build it changes — the transcript of
this work *is* what gets scored later, so there's no special mode to turn on.

### 5. Submit
Two ways, pick whichever's easier:

**CLI** (works from any machine with Node 18+, no repo checkout needed):
```bash
npx nideknil-submit <your access_token>
```
- Scopes to the Claude Code "project" matching your current directory
- If it finds multiple sessions (e.g. you also did unrelated work in the same folder), it lists
  them and lets you pick by number, a date, or a date range (`--since`/`--until`) — it does **not**
  guess which sessions are "about the assignment," only which ones fall in a time window you choose
- Scrubs secrets locally before anything leaves your machine, shows you exactly what will be sent,
  and asks for confirmation before uploading
- `--dry-run` previews everything with zero upload, if you want to check first

**Web portal:**
Go to `https://www.nideknil.in/assignment/<token>`, drag and drop your `.jsonl` session file(s).

Either path hits the same endpoint and the same scoring pipeline.

### 6. Check your report
Once status flips to `analyzed` (usually within a couple minutes), ask your connected Claude
Code: *"what's my report status"* — or just check the portal page. You'll only ever see your own
report, never another candidate's.

## Command cheat sheet

```bash
# Candidate: connect
claude mcp add --transport http nideknil-assignment https://api.nideknil.in/mcp/ \
  --header "Authorization: Bearer <access_token>"

# Candidate: submit
npx nideknil-submit <access_token>
npx nideknil-submit <access_token> --since 2026-07-05              # only sessions from that date on
npx nideknil-submit <access_token> --since 2026-07-05 --until 2026-07-05   # just that one day
npx nideknil-submit <access_token> --dry-run                       # preview, no upload

# Recruiter: get a JWT (if scripting from terminal instead of the web UI)
JWT=$(curl -s -X POST https://api.nideknil.in/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@company.com","password":"..."}' \
  | python3 -c "import json,sys; print(json.load(sys.stdin)['access_token'])")

# Recruiter: generate an MCP key
curl -s -X POST https://api.nideknil.in/api/recruiter/mcp-keys -H "Authorization: Bearer $JWT"

# Recruiter: connect (use the connect_command from the response above — already has the trailing slash)
claude mcp add --transport http nideknil-recruiter https://api.nideknil.in/mcp-recruiter/ \
  --header "Authorization: Bearer <key>"

# Either side: check a connection
claude mcp get nideknil-assignment
claude mcp get nideknil-recruiter
claude mcp list

# Remove a stale/wrong connection before re-adding
claude mcp remove <name> -s local
```

## Troubleshooting

**`claude mcp get <name>` shows "✘ Failed to connect"**
Almost always the missing trailing slash. The URL must be `.../mcp/` or `.../mcp-recruiter/`, not
`.../mcp` or `.../mcp-recruiter`. Remove and re-add with the slash:
```bash
claude mcp remove <name> -s local
claude mcp add --transport http <name> https://api.nideknil.in/mcp/ --header "Authorization: Bearer <token>"
```

**`MCP server <name> already exists in local config`**
You already have one registered under that name (maybe from an earlier attempt with the wrong
URL). Remove it first, then re-add:
```bash
claude mcp remove <name> -s local
```

**`npx nideknil-submit` → `npm error 404`**
The package needs to be published to npm for this to work from outside the repo — this was a real
gap that's since been fixed (`nideknil-submit@1.0.0` is live). If you see this again, check
`npm view nideknil-submit` to confirm the package still resolves; if not, the web portal
(`https://www.nideknil.in/assignment/<token>`) always works as a fallback regardless of npm status.

**A submission is stuck on "submitted" and never reaches "analyzed"/"failed"**
Check the Celery worker is actually running and picking up tasks:
```bash
docker compose -f docker-compose.prod.yml logs -f celery-worker | grep -i fluency
```
If a submission previously failed due to an infra issue and got "fixed" retroactively (e.g. an S3
permission or shared-storage fix), re-submit fresh rather than relying on the retry endpoint —
retry re-scores an *already-stored* transcript, and if the stored file itself was lost (e.g. it was
only ever written to a container's local disk that's since been recreated), retrying won't recover it.

**The recruiter's Assignments/MCP-settings page is stuck on "Processing…" forever**
Should be fixed as of the current frontend — a failed fetch now falls through to an empty
state/error message instead of spinning indefinitely. If you still see this, hard-refresh first;
if it persists, the underlying API call is genuinely failing (check the network tab / backend
logs), not just a UI bug.
